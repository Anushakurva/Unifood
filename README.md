# Unifood site — editable source

The HTML pages now load pre-built, minified files (`tailwind.min.css`,
`styles.min.css`, `main.min.js`, `app.min.js`) instead of pulling the Tailwind
CDN script and full-size scripts on every visit. That's what fixed the
PageSpeed "unused CSS/JS" and "long main-thread task" warnings — the browser
no longer compiles Tailwind's entire utility set at runtime.

**Edit the files in this `src/` folder**, not the `.min.` files at the top
level — the minified files are generated output and get overwritten on
rebuild.

- `src/styles.css` → `styles.min.css`
- `src/main.js` → `main.min.js` (index.html's gallery, booking form, GSAP animation, sliders)
- `src/app.js` → `app.min.js` (menu.html's ordering logic)
- `tailwind.min.css` is generated by scanning `index.html`, `menu.html`, and
  the two JS files for class names — if you add new Tailwind classes
  anywhere, you must rebuild this file or the new classes won't have any CSS.

## Rebuilding after an edit

You'll need Node.js installed. From this project's root folder:

```bash
npm install -D tailwindcss terser

# Rebuild Tailwind (scans *.html and *.js for classes actually used)
npx tailwindcss -i ./src/tailwind-input.css -o ./tailwind.min.css --minify

# Re-minify JS
npx terser src/main.js -c -m -o main.min.js
npx terser src/app.js -c -m -o app.min.js
```

Where `src/tailwind-input.css` just contains:
```css
@tailwind base;
@tailwind components;
@tailwind utilities;
```

If you don't want to deal with a build step at all, you can swap the
`tailwind.min.css` link back to `<script src="https://cdn.tailwindcss.com">`
temporarily while you iterate, then rebuild before publishing.
